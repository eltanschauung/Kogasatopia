# Inventory/hats stress investigation — 2026-10-11

## Outcome

Nine completed 16-bot trials reproduced substantial inventory-related stalls.
The strongest native evidence is **SourceHook memory-protection/map lookup
work during hook attachment and removal**, not the small native whitelist
lookup itself. The bottleneck persisted with sigsegv absent and CheckLag off.
This narrows a reproducible path; it does not prove that every earlier human
server incident had this same origin or that sigsegv has no other problems.

Testing stopped automatically when a human joined during the next trial's
setup. That aborted trial and earlier harness-failure trials are not evidence.
The operator approved restoration/restart of the original Weapons/native
builds and sigsegv, retaining main's lightweight CheckLag self-diagnostics.

## Realistic paired data and equal hat coverage

The fixture came from the last ten completed non-MGE matches. Sixteen distinct
participants supplied their current saved custom-loadout cookies. Each profile
uses **one source SteamID64 for both weapons and hats**, including that identity's
other supported Steam representations in the cookie lookup. Source identities
are omitted from the fixture; test API overrides/grants are in-memory, bot-only
and client-serial-bound. No real-client cookie or entitlement is changed.

The fixture contains 89 weapon selections across classes and 31 hat selections.
87 weapon selections are valid in the live item registry; two obsolete ones
are skipped and counted. Initial class preference uses the source player's
most-shot class with a saved custom loadout. Class-cycling tests deliberately
exercise all classes. These are current saved choices, not historical Steam
inventory snapshots at the time those matches were played.

Forced paired and hats-only trials maintained **31 actual custom wearables**
throughout their sampled coverage. Weapons-only trials verified zero custom
hats; hats-only trials verified zero custom weapons. Forced recreation applies
to both domains. A late cookie callback originally cleared lab hats; the lab
now preserves its session overrides and prohibits their persistence.

Hats have dedicated ApplyFrame/Equip/CreateWearable/ApplyModel measurements.
One retained staggered snapshot measured hat Equip at 0.476 ms peak,
CreateWearable at 0.311 ms and ApplyModel at 0.024 ms. These are one warm
snapshot's inclusive timings, not a universal guarantee about every hat.

## Native origin evidence

Sampling was bounded to the TF2 main thread, 49 Hz, 8-KiB DWARF stacks and
short captures. No system-wide recording or large symbol downloads. The
32-bit decoder resolved native and SourcePawn JIT symbols; raw data stays
private and is not committed.

Representative stacks:

```
libc getc/fscanf
  <- SourceHook::MakePageWritable
  <- CVfnPtr::Revert / RemoveHookByID
  <- CritManager::OnEntityDestroyed (game.tf2.ext)
  <- SDKHooks::HandleEntityDeleted
  <- UTIL_Remove
  <- CTFPlayer::ValidateWeapons

libc getc/fscanf
  <- SourceHook::MakePageWritable
  <- RemoveHookByID
  <- FrameCleanupHooks (dhooks.ext)
  <- SourceMod timer/frame dispatch

libc getc/fscanf
  <- SourceHook::MakePageWritable / AddHook
  <- DHooks HookEntity
  <- WeaponsSound_HookWeaponEntity
```

The sig-off capture had 1,069 sampled stacks: 370 contained
`MakePageWritable`, 162 `ModuleInMemory`, 156 critical-hook entity cleanup
and 188 DHooks frame cleanup. These sets are inclusive; do not add overlapping
counts or interpret them as exact exclusive milliseconds. The sig-on capture
also strongly featured these paths.

The installed Metamod source explains this: `GetPageBits()` opens
`/proc/self/maps` and scans it using fscanf plus a byte-at-a-time fgetc loop.
`ModuleInMemory()` separately scans that file. `CVfnPtr::Revert()` checks the
mapping and then patches/restores the virtual entry. The SourceMod TF2
extension installs/removes two critical-calculation hooks per weapon. Weapons
also installs per-entity sound/deploy hooks. Repeated replacement therefore
multiplies these scans. The tested processes had roughly 896–972 mappings.

Host samples during forced stalls showed almost all interval wall time spent
on the main-thread CPU, with no major page faults or disk reads. Conversely,
the ~180 ms idle-batching gaps had only ~17–25 ms CPU in ~195 ms intervals.
Those idle gaps are a separate confound, not an inventory CPU stall.

The old 128-call buffer lost dense burst context. It is now 4096 on this debug
branch. Tick-only matching also missed timers executed before OnGameFrame at
the same tick; observer-boundary sequences now associate completed scopes
with the correct gap. A refined alert matched a 529.67 ms frame to a 75.12 ms
ManageRegularWeapons interval **on that frame**, with zero overwritten calls.
That interval is only one of the frame's multiple operations; the remaining
454.55 ms is not automatically blamed on another plugin.

## CheckLag observer contribution

Mode 0: zero collected self work; large stalls remained.
Mode 1: approximately **0.172 ms/s** measured completed root observer work,
peak sampled tick 0.446 ms. The equivalent warm mode-0/mode-1 trials performed
928 operations each and had very similar rates (19.93 vs 19.78 Hz).
Mode 2: about **18–23 ms/s** root observer work under this stress, with
7–18 ms sampled tick peaks. Heavy profiling is not free; leave mode 1 as the
production default.

Self costs include CheckLag's synchronous callees, not all Weapons/DHooks
instrumentation, external perf sampling or later asynchronous database work.
One-second sample windows are approximate, not an exact exclusive CPU budget.
Nested categories must never be summed. Alert pipeline completion is logged
separately to avoid omitting its own observer cost.

Most measured native loadout calls peaked around 0.2–0.3 ms; one refined trial
had an 8.08 ms resolver callback outlier. Its total measured loadout work was
56 ms across the trial, insufficient to account for the repeated large frames.

## Follow-up direction and limitations

The next focused experiment should reduce unnecessary per-weapon virtual-hook
churn (especially hooks installed even without the corresponding sound
attribute) and investigate efficient, correct SourceHook memory-map/protection
checks. A native detour with shared lifetime may avoid entity-by-entity
attachment/removal, but needs subclass/ABI coverage and unload safety testing.
Do not bypass memory-validity checks or hard-code page permissions as a fix.
No Metamod/TF2-extension rewrite was deployed by this investigation.

Nine trials completed without new Weapons, CheckLag, lab-plugin or native-hook
errors. Existing RTD invalid-handle errors recurred, and a Whaletracker call
into a paused provider appeared around lifecycle transitions. These are
separate findings and were not silently modified.

TF2 bots are not sixteen networked humans. Steam inventory replies, client
downloads and real-client snapshot costs are not faithfully simulated. The
smaller staggered workload mostly maintained ~66 Hz; deliberate batch overload
does not establish that an ordinary human switch will always reproduce these
long frames. A controlled real-client follow-up and reverse-order sig benchmark
would strengthen attribution. All generated fixtures, cookies, logs, IDs and
raw captures remain outside Git.
